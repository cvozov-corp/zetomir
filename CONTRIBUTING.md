# Участие в разработке

## Рабочий процесс

1. Создайте отдельную ветку для задачи.
2. Перед изменениями запустите `make test` и `make zeto-check`.
3. Делайте небольшие коммиты с одной понятной целью.
4. Добавляйте тесты или точные шаги ручной проверки.
5. Обновляйте README и профильную документацию.
6. В pull request укажите затронутые подсистемы, тесты и ограничения.

## Правила ядра

- Ядро собирается freestanding; не используйте функции libc без собственной реализации.
- Соблюдайте `-Wall -Wextra -Werror`.
- Для архитектурного кода явно документируйте привилегии CPU, регистры и побочные эффекты.
- Не включайте прерывания до установки корректных обработчиков и контроллера IRQ.
- Не используйте память или адреса устройств без проверки доступности и диапазонов.
- Драйвер должен корректно сообщать о неподдерживаемом устройстве.
- Не выдавайте stub за готовую реализацию.

## Проверки перед отправкой

```bash
make test
make zeto-check
make clean
make CROSS= -j"$(nproc)"
```

Если установлен cross-compiler, дополнительно:

```bash
make clean
make -j"$(nproc)"
```

Если менялись загрузка, драйверы или графика, приложите параметры VM и результаты загрузки. Не заявляйте физическую совместимость без теста на реальном устройстве.
